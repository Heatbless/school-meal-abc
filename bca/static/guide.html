A week is one solution

Monday through Friday each need a staple, protein dish, vegetable dish and fruit. That gives a food source 20 categorical choices. Daily serving counts are fixed planning inputs.

The Python host evaluates nutrition for one serving, then calculates school-wide cost and ingredient quantities using the required serving count. It estimates preparation in batches.

The colony diagram is schematic. Source positions help you follow bees; the optimization variables are the menu choices.

Three roles, one shared search

Employed bees · improve a source

Each employed bee owns one candidate week. It uses a distinct partner source to propose a one-component substitution. When source and partner offer the same choices, an alternative eligible component can introduce a new choice. The better schedule survives.

Onlooker bees · follow promising sources

Onlookers choose a source using fitness-weighted probabilities, then try another local substitution. A more attractive source gets a greater chance of selection, but every source retains a chance.

Scout bees · explore a fresh week

After enough consecutive failed improvement attempts, a source becomes eligible for abandonment. Its employed bee takes the scout role and samples a replacement week from the eligible catalog.

A cycle follows employed, onlooker and scout phases. This is a discrete ABC adaptation: component substitutions express a local neighborhood for categorical meals.

A lower score is better

Each score is a weighted sum of normalized terms. Normalization makes different units comparable. Open the score breakdown to see what contributed.

S = w_cost × cost + w_budget × budget + w_nutrition × nutrition + w_variety × variety + w_workload × workload
TermHow it is measured
CostFive-day cost divided by the five-day budget.
BudgetAverage daily cost overrun divided by each day's budget. Days within budget contribute zero.
NutritionAverage daily sum of normalized energy-range, protein-minimum and fiber-minimum violations.
VarietyProtein uses and identical-menu uses beyond their configured repetition limits, divided by five.
WorkloadAverage daily person-minute overrun divided by kitchen capacity.

Nutrition is measured per serving

energy deviation = max(0, (minimum − energy) / minimum) + max(0, (energy − maximum) / maximum) protein deviation = max(0, (protein minimum − protein) / protein minimum) fiber deviation = max(0, (fiber minimum − fiber) / fiber minimum)

School quantities are measured separately

daily cost = cost per serving × required servings ingredient quantity = amount per serving × required servings batches = ceiling(required servings / component batch size) daily workload = sum(batches × person-minutes per batch)

Ingredient totals retain their units. A gram quantity and a piece count remain separate entries. Dietary exclusions remove incompatible choices before the search; budget, nutrition, variety and capacity preferences create visible target violations.

Why did an onlooker choose that source?

fitness(i) = 1 / (1 + score(i)) probability(i) = fitness(i) / sum(fitness of all sources)

The event inspector shows probabilities used for the actual draw. Following an accepted move, the current population's probabilities may change.

A substitution is accepted only when its score strictly improves. Equal or worse scores count as unsuccessful attempts. A successful attempt resets that source's failure counter.

Keep the best, even when sources change

Best-ever memory is separate from the current food sources. A scout replacement cannot erase an earlier best result. The convergence chart follows this retained best score.

The run stops at its cycle limit, at the optional number of cycles without a best improvement, or when you choose Stop. Completion gives the stopping reason.

Use the same catalog, settings and seed to repeat a run. Exports keep these inputs alongside the result. The app reports the best observed solution and its remaining violations.

Read an event, then advance

  1. Initialize creates valid candidate schedules on the host.
  2. Step advances one host-generated event.
  3. Play repeatedly requests advancement. Speed changes the delay between requests; each request advances one event.
  4. Pause stops further advancement requests; an in-flight request can finish.
  5. Select a source to inspect its current schedule, score and failure count.
  6. Reset deletes the current run and loads the saved configuration and seed. Reloading or returning to the lab also retires this tab's previous run.

The browser sends controls and renders results. All search, selection, scoring and random generation execute on the Python host.

Demonstration data you can change

The school-menu example is inspired by MBG, Indonesia's Makan Bergizi Gratis program. The catalog's prices, ingredient amounts, nutrition values and target defaults are demonstration inputs. Edit them in the planner or import a configuration JSON file. Two protein options labeled demo deliberately expose tradeoffs: a cheap light portion may miss nutrition targets, while a premium dish can exceed budget and kitchen capacity.
